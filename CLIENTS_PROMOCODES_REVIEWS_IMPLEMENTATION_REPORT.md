### 1. База данных и схема

**Файлы:** `prisma/schema.prisma`, `prisma/migrations/001_add_clients_promocodes_reviews_features.sql`

#### Добавлены поля в модель User:
- `lastSeenAt` — timestamp последней активности
- `blockedReason` — причина блокировки
- `blockedAt` — дата блокировки
- `blockedBy` — ID администратора, заблокировавшего пользователя (с FK)

#### Расширена модель Promocode:
- `name` — название акции
- `description` — описание
- `maxDiscountAmount` — максимальная сумма скидки для процентных промокодов
- `usesPerCustomer` — лимит использований на одного клиента
- `firstOrderOnly` — флаг «только для первого заказа»
- `createdAt`, `updatedAt` — timestamp создания и обновления

#### Создана новая модель PromocodeUsage:
- `id`, `promocodeId`, `userId`, `orderId`
- `discountAmount` — размер применённой скидки
- `createdAt` — дата использования

#### Добавлен enum ReviewStatus:
- `pending` — на модерации
- `approved` — одобрен
- `rejected` — отклонён
- `hidden` — скрыт

#### Расширена модель Review:
- `status` — статус модерации (ReviewStatus)
- `moderatedBy` — ID модератора (FK на users)
- `moderatedAt` — дата модерации
- `rejectionReason` — причина отклонения

**Миграция применена:** ✅ Все изменения успешно применены к PostgreSQL БД

### 2. API Endpoints

#### 2.1 Клиенты

**GET `/api/admin/users`**
- Список всех пользователей с пагинацией (20 на страницу)
- Поиск по имени, email, телефону
- Фильтры: по роли, статусу блокировки
- Сортировка
- Онлайн-статус: вычисляется на основе `lastSeenAt` (онлайн если < 2 минут)
- Статистика: кол-во заказов, сумма, средний чек

**GET `/api/admin/users/[id]`**
- Детальная информация о пользователе
- История заказов (последние 50)
- Баланс лояльности
- Отзывы пользователя
- Полная статистика

**PATCH `/api/admin/users`**
- Действия: `block`, `unblock`
- Блокировка с обязательной причиной
- Валидация: нельзя заблокировать себя или последнего админа
- Логирование в `activity_logs`

**POST `/api/users/heartbeat`**
- Обновление `lastSeenAt` авторизованного пользователя
- Вызывается каждые 2 минуты для активных сессий
- Throttling: обновление БД раз в 30 секунд (снижение нагрузки)

#### 2.2 Промокоды

**GET `/api/admin/promocodes`**
- Список всех промокодов с пагинацией
- Поиск по коду и названию
- Фильтры по статусу: active, scheduled, expired, depleted
- Вычисляемый статус на основе дат и лимитов
- Статистика: использования, общая скидка, кол-во заказов

**POST `/api/admin/promocodes`**
- Создание промокода
- Валидация: уникальность кода, корректность дат, размер скидки
- Автоматическая нормализация кода (toUpperCase)
- Логирование создания

**GET `/api/admin/promocodes/[id]`**
- Детальная информация о промокоде
- История использований (100 последних)
- Заказы с промокодом (100 последних)
- Полная статистика

**PATCH `/api/admin/promocodes/[id]`**
- Редактирование всех полей промокода
- Валидация изменений
- Логирование обновлений

**DELETE `/api/admin/promocodes/[id]`**
- Удаление промокода
- Защита: нельзя удалить, если использовался в заказах (предлагается деактивация)
- Логирование удаления

**POST `/api/orders/apply-promocode`**
- **Полная серверная валидация:**
  - Существование и активность промокода
  - Проверка дат действия
  - Общий лимит использований
  - Минимальная сумма заказа
  - Лимит на пользователя (`usesPerCustomer`)
  - Ограничение на первый заказ (`firstOrderOnly`)
  - Применимость к товарам/категориям
- Расчёт размера скидки:
  - Процентная с учётом `maxDiscountAmount`
  - Фиксированная
  - Ограничение: скидка не превышает сумму заказа
- Возвращает: промокод, размер скидки, новую итоговую сумму

#### 2.3 Отзывы

**GET `/api/admin/reviews`**
- Список отзывов с пагинацией
- Поиск по тексту и имени автора
- Фильтры: статус, рейтинг, товар
- Include: пользователь (с аватаром), товар, заказ, модератор

**GET `/api/admin/reviews/[id]`**
- Детальная информация об отзыве
- Полные данные пользователя и заказа

**PATCH `/api/admin/reviews/[id]`**
- Действия модерации:
  - `approve` — одобрить и опубликовать
  - `reject` — отклонить с обязательной причиной
  - `hide` — скрыть опубликованный
  - `restore` — вернуть в статус pending
- Автоматическое заполнение `moderatedBy`, `moderatedAt`
- Логирование всех действий

**DELETE `/api/admin/reviews/[id]`**
- Удаление отзыва
- Логирование

**GET `/api/reviews` (публичный)**
- Только одобренные отзывы (`status=approved`, `isPublished=true`)
- Пагинация
- Фильтр по товару
- Расчёт среднего рейтинга

**POST `/api/reviews` (публичный)**
- Создание отзыва авторизованным пользователем
- Валидация:
  - Рейтинг 1-5
  - Текст 10-1000 символов
  - Проверка блокировки пользователя
  - Проверка дубликатов (один отзыв на товар)
  - Проверка принадлежности заказа (если указан `orderId`)
  - Статус заказа `COMPLETED`
- Отзыв создаётся со статусом `pending`, требует модерации

  - Товар (если указан)

  - Статус (badge)

- Поиск по тексту/автору
- Фильтры: статус, рейтинг
- Статистика по каждому статусу (4 карточки-счётчика)

  - Одобрить — сразу публикует
  - Отклонить — с модальным окном для причины
  - Скрыть — для опубликованных
- Модальное окно: превью отзыва + подтверждение действия

#### 4.2 Применение промокода в корзине

**Файл:** `app/cart/page.tsx`

**Функциональность:**
- Поле ввода промокода (автоматический toUpperCase)

  - Успех: зелёная плашка с кодом и названием, кнопка «Удалить»
  - Ошибка: красный текст с описанием
- Пересчёт итоговой суммы:
  - Товары
  - Скидка (зелёным цветом)
  - Итого

**Файлы:** `lib/useHeartbeat.ts`, `app/components/HeartbeatProvider.tsx`, `app/layout.tsx`

**Функциональность:**
- Автоматическая отправка heartbeat каждые 2 минуты
- Дополнительная отправка при активности (клики, клавиатура, скролл) с throttling (раз в минуту)
- Работает для всех авторизованных пользователей
- Не блокирует работу приложения при ошибках

## 🔒 Безопасность

1. **Серверная авторизация:** все API проверяют права через `requireAuth()`
2. **Валидация данных:** проверка всех входных параметров
3. **Защита от дубликатов:**
   - Уникальность кодов промокодов
   - Один отзыв на товар от пользователя
4. **Атомарные операции:** счётчик использований промокода обновляется транзакционно
5. **Проверка принадлежности:** нельзя заблокировать себя, оставить отзыв на чужой заказ
6. **Логирование:** все административные действия записываются в `activity_logs`
