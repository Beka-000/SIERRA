# Sierra Coffee - Полная реализация разделов Клиенты, Промокоды и Отзывы

## 📋 Обзор

Полностью реализованы три ключевых раздела Sierra Coffee с интеграцией реальной базы данных, серверной валидацией, ролевым доступом и без использования моков. Все функции протестированы и готовы к использованию.

## ✅ Выполненные задачи

### 1. База данных (Schema & Migration)

**Обновлена schema.prisma:**
- `User` модель:
  - `lastSeenAt` - timestamp последней активности пользователя
  - `blockedReason` - причина блокировки
  - `blockedAt` - дата и время блокировки
  - `blockedBy` - ID администратора, заблокировавшего пользователя

- `Promocode` модель:
  - `name` - название промокода
  - `description` - описание
  - `maxDiscountAmount` - максимальная сумма скидки для процентных промокодов
  - `usesPerCustomer` - лимит использования на одного пользователя
  - `firstOrderOnly` - флаг "только для первого заказа"

- `ReviewStatus` enum: `pending`, `approved`, `rejected`, `hidden`

- `Review` модель:
  - `status` - статус отзыва (enum)
  - `moderatedBy` - ID модератора
  - `moderatedAt` - дата модерации
  - `rejectionReason` - причина отклонения

- `PromocodeUsage` модель (новая таблица):
  - Отслеживание использования промокодов
  - Связь с пользователем, заказом и промокодом
  - Сумма скидки

**Миграция:**
- Создан SQL файл `prisma/migrations/001_add_clients_promocodes_reviews_features.sql`
- Применён через `scripts/apply-migration-v2.ts` с обработкой существующих полей
- Prisma Client регенерирован

### 2. API Клиентов

**GET /api/admin/users**
- Список пользователей с пагинацией (limit, offset)
- Поиск по имени, email, телефону
- Фильтрация по статусу (active, blocked), роли
- Сортировка по дате регистрации, последней активности
- Статистика заказов и баланса
- Требует роль admin/manager

**GET /api/admin/users/[id]**
- Детальная информация о пользователе
- История заказов
- Статистика (общая сумма, количество заказов)
- Данные лояльности

**PATCH /api/admin/users/[id]**
- Блокировка/разблокировка пользователя
- Обязательное указание причины при блокировке
- Логирование действий в ActivityLog
- Требует роль admin/manager

**POST /api/users/heartbeat**
- Обновление lastSeenAt каждые 2 минуты
- Throttling на клиенте (обновление БД раз в 30 сек)
- Автоматическая интеграция через HeartbeatProvider

### 3. API Промокодов

**GET /api/admin/promocodes**
- Список с пагинацией и поиском
- Фильтрация по статусу (active, scheduled, expired, depleted)
- Статистика использования
- Вычисление актуального статуса на основе дат и лимитов

**POST /api/admin/promocodes**
- Создание промокода с полной валидацией:
  - Уникальность кода
  - Корректность дат (validFrom < validUntil)
  - Корректность сумм и процентов
  - Валидация применимых товаров/категорий
- Автоматическая генерация кода

**GET /api/admin/promocodes/[id]**
- Детальная информация с статистикой
- История использования

**PATCH /api/admin/promocodes/[id]**
- Обновление параметров
- Активация/деактивация
- Валидация изменений

**DELETE /api/admin/promocodes/[id]**
- Удаление промокода (soft delete через isActive)

**POST /api/orders/apply-promocode**
- Полная серверная валидация:
  - Существование и активность
  - Проверка дат (validFrom, validUntil)
  - Лимиты (usageLimit, usesPerCustomer)
  - Минимальная сумма заказа
  - Применимость к товарам/категориям
  - Условие "первый заказ" (firstOrderOnly)
- Расчёт скидки (процент/фикс с учетом maxDiscountAmount)
- Возврат детальной информации для отображения

### 4. API Отзывов

**GET /api/reviews (публичный)**
- Только одобренные отзывы
- Фильтрация по товару
- Пагинация
- Расчёт среднего рейтинга

**POST /api/reviews**
- Создание отзыва авторизованным пользователем
- Валидация:
  - Проверка блокировки пользователя
  - Рейтинг 1-5
  - Минимальная длина текста (10 символов)
  - Проверка дубликатов
  - Принадлежность заказа пользователю
- Статус по умолчанию: pending

**GET /api/admin/reviews**
- Список всех отзывов с фильтрами:
  - По статусу (pending, approved, rejected, hidden)
  - По рейтингу
  - По товару
  - Поиск по тексту
- Пагинация
- Включает информацию об авторе и товаре

**GET /api/admin/reviews/[id]**
- Детальная информация об отзыве
- История модерации

**PATCH /api/admin/reviews/[id]**
- Действия модерации:
  - `approve` - одобрить
  - `reject` - отклонить (с обязательной причиной)
  - `hide` - скрыть
  - `restore` - восстановить
- Логирование модерации
- Требует роль admin/manager

**DELETE /api/admin/reviews/[id]**
- Удаление отзыва (hard delete)

## 📝 Notes

### Технические решения

**Heartbeat Implementation:**
- Выбран подход с периодическими запросами вместо WebSocket для простоты
- Throttling на клиенте предотвращает избыточную нагрузку на БД
- 2 минуты выбраны как разумный баланс между точностью и нагрузкой

**Promocode Validation:**
- Вся логика валидации дублируется в двух местах:
  1. `/api/orders/apply-promocode` - для проверки в корзине
  2. `/api/orders` (POST) - для финальной проверки при создании заказа
- Это предотвращает race conditions и подмену данных

**SessionStorage для промокода:**
- Выбран вместо query params (видимо в URL) и global state (сложность)
- Очищается после успешного создания заказа
- Безопасен, так как финальная валидация на сервере

**Модерация отзывов:**
- Enum со статусами вместо boolean флагов для гибкости
- Поле rejectionReason для обратной связи
- Hidden статус позволяет временно скрыть без удаления
